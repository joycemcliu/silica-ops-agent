## Impact and scope

## Triggering device

```text
SCSI\DISK&VEN_&PROD_\4&E4909E8&0&040000
```

This `DiskDrive` entry had an existing but empty `FriendlyName` override. The separate system drive was NVMe `MTFDKBA512TFH-1BC1AABHA`, size `512110190592` bytes. Enumeration index 58 is unrelated to disk index 0.

The missing-property case is different: MultiInput can fall back to `DeviceDesc` when the override is absent. The native bug was triggered by an existing property containing an empty string.

## Native evidence

The plugin is RavingBots MultiInput, not Rewired. Initialization scans all Windows device classes, not only USB/input devices. Native disassembly established these locations in the inspected binary:

- Preferred image base: `0x68600000`; observed loaded base: `0x6BCA0000`.
- Creation export near RVA `0x1820`; captured return `rb_minput_create+0x92` corresponds to RVA `0x18B2`.
- Enumeration starts near RVA `0xC660`; `SetupDiGetClassDevs` flags were `0x16`.
- Device index stored at `0xc(%rbp)`.
- Friendly-name query near RVA `0xC2A0`, property `0xC`; missing property/error 13 leads to description fallback.
- Empty-name branch near RVA `0xC94C`; cleanup jumps at `0xCA99` / `0xCAA4` return to `0xC810` without advancing the index.
- Normal index increment is at `0xCDD0`.

All affected games stopped logging around Photon `Connecting to server - 127.0.0.1:5055`; this was a misleading last log, not evidence that Photon caused the hang. Identical native binaries in working games do not establish why those games avoided the path.

## Repair and recovery timeline

1. The debugging agent backed up the device identity, property type and original bytes to the server backup listed above.
2. At **2026-11-02 11:39:50 Asia/Hong_Kong**, the agent removed only the empty property using `SetupDiSetDeviceRegistryPropertyW(..., 12, NULL, 0)`.
3. The already-running AmberSky process, PID `15596`, became responsive without a restart. Its cached input enumeration logged a native exception during live removal, then continued.
4. Photon connected at **11:39:52**. All six player IDs eventually connected; duplicate stale actors resolved back to 6/6. Both Consul checks passed.
5. Fresh standalone native initialization completed and exited 0. No disk contents, drivers, storage configuration, deployment files or repository code were changed.

Future remediation under the linked runbook is human-only. The extracted reusable script was not the script executed in this historical repair.
